Root cause: Task 14's full-workspace spanning — every vertical guide strip was top:0/bottom:0 of the content box, so one page's guides were drawn straight through every page below it; and a horizontal guide dragged more than the 64px inter-page gap past an interior page's edge landed on the next page's band.
- PAGE-SCOPED RENDERING: UserGuidesOverlay now computes each page's band; a vertical guide strip spans [own page top − tail, own page bottom + tail] with tails = full 120px pasteboard at the content-box outer edges and 32px (half the inter-page gap) toward neighbors — each page owns one half of every gap, so a line can physically never cross another page. Horizontal guides keep the full-width line but their DRAWN position is clamped per page to the same rule (guards legacy stored values beyond the band).
- DASHED OFF-PAGE: any portion of a guide outside its own page renders dashed (repeating-linear-gradient 7px dash/6px gap): the pasteboard tails always, and the ENTIRE line when the guide's coordinate is off-page (x<0|x>W or y<0|y>H) — a lost guide is instantly distinguishable from on-page content. On-page span stays solid 1px core + 3px 35% halo; drag highlight amber still applies. Segments carry data-guide-seg="head|main|tail" + data-guide-core; strips carry data-guide-off for tests.
- POSITION CLAMPS: new store exports PAGE_GAP_PX=64 (Canvas GAP now imports it — single source) and hGuideBounds(docH, zoom, isFirst, isLast) = [−(first?120:64)/zoom, H + (last?120:64)/zoom]; moveGuide + addGuide clamp horizontal guides to it (addGuide clamps both axes as a safety net), the ruler-drop ghost/commit range uses it, and GuidesDialog validates against it with a "stopping at the neighboring page" toast. Vertical guides keep the full left/right pasteboard (single-column layout — no page beside them).
